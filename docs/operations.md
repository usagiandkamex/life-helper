# 運用

## 知識ベース（Azure Files の `/data/knowledge`）

| フォルダ | 内容 | 編集 |
|---|---|---|
| `profile/` | 自分の基本情報・回答の好み（毎回の会話に反映） | 画面から本人だけ |
| `memories/` | 会話から覚えたこと | Copilot（チャットでは承認したときだけ）・画面 |
| `notes/`・`plans/` | ノート、ライフプランの記録 | Copilot（チャットでは承認したときだけ）・画面 |
| `docs/` | アップロード資料（Markdown に変換。原本は保存しない。スキャン PDF は非対応） | 画面 |
| `money/portfolio.yaml` | 保有銘柄 | 資産画面・ツール |

- チャットの知識ベースは既定で読み取り専用です。Copilot がファイルを書き換えようとすると、チャットに変更内容（差分）と「承認」「この回答中はすべて承認」「却下」のボタンが出ます。承認したときだけ保存されます。
  - 10 分以内に選ばなかったとき、回答を中断したとき、回答が終わったときは保存しません。承認を待っているあいだにファイルが画面などから変更された場合も、上書きせずに中止します。
  - 保有銘柄・株価・基準価額の更新ツールは、これまでどおり承認なしで動きます。オートメーションは「書き換えを許可」の設定に従います（承認は求めません）。

- 画面「知識・メモリ」の **ZIP で書き出し** でいつでもバックアップできます。
- Azure Files の共有は、削除しても 14 日間は復元できます（論理削除）。定期スナップショットが必要なら Azure Backup（有料）を検討します（使う前に費用を判断）。
- マイナンバー・口座番号・カード番号・パスワードはファイルに保存されません（Copilot の書き込みは拒否、アップロードは伏せ字で保存）。Copilot は API キーなどの秘密情報も書き込めません。

## 年度ごとの税パラメータ

`app/backend/src/life_helper/resources/tax_params/<年>.yaml` を毎年更新します（ブランチ → PR で変更）。
出典（国税庁・総務省）で値を確認して `status: verified` にします。`provisional` の間、および未登録の年度で計算すると、結果に警告が表示されます。

## 証券会社 CSV の列

`resources/broker_csv/<証券会社>.yaml` の見出し候補に実際の CSV の見出しを追加すれば、コード変更なしで対応できます。見出しが合わない CSV は取り込まずにエラーにします。

## 積立・買い増しの反映

保有銘柄は購入ごとの履歴ではなく、銘柄・口座ごとの合計（数量・取得額）で管理します。積立や買い増しの後は、次のどちらかで更新します。

- 証券会社の保有証券 CSV を取り込み直す。保有銘柄は CSV の内容にまるごと置き換わります（画面で編集した値も CSV の値になります）。
- 資産画面の保有銘柄の「編集」で、「買い増し分を加算」に今回の購入数量と購入金額（手数料を含む受渡金額）を入力する。
  証券会社の画面と合わせたいときは「合計値を直接編集」で合計を上書きします。

保存するのは加算後の合計で、編集を始めた時点の合計も一緒に送ります。二重に送信しても二重には加算されず、その間にほかの操作で合計が変わっていたら
更新せずに最新の値を表示し直します。CSV から取り込んだ銘柄の数量を変えると、株価・基準価額を更新するまでは CSV の評価額を数量で按分した値を評価額にします
（CSV の現在値は米国株だと USD のため、円の単価としては使いません）。

## オートメーション

- ACA ジョブが 15 分ごとに起動し、期限が来たものだけを実行します（1 回最大 20 分）。時刻は日本時間で指定します。
- 1 回の実行で Copilot のリクエストを 1 回以上使います。画面の推定回数と月間上限（既定 300 回、`LH_AUTOMATION_MONTHLY_RUN_LIMIT`）で管理します。
- 既定は読み取り専用です。メモリ・ノート・保有銘柄を書き換えるものだけ「書き換えを許可」をオンにします。
- 使うコネクタは、オートメーションごとに選んだものだけが有効になります。
- GitHub Issue での通知は「GitHub で通知する」をオンにしたものだけです。トークンが無効になったときの再ログイン通知だけは、1 日 1 回自動で送ります。

例: 楽天トラベルの空室チェック

| 項目 | 設定 |
|---|---|
| 指示 | 12/30〜12/31、大人 2 名で施設番号 ○○ の空室を search_rakuten_vacancy で確認して |
| 周期 | 毎日 9:00 |
| コネクタ | 楽天トラベル空室検索 |
| 通知 | GitHub で通知する / ツールの結果の値で判定 `vacancy_count > 0` / 前回は満たさず今回満たしたときだけ |

空室は確認時点のもので、予約は自分で行います。

### チャットでの表示

- 終わった実行は、チャットの会話一覧に 🤖 付きで出ます（未読は ●）。まとめ方はオートメーションの「会話」設定に従います。
  - 毎回新しい会話: 実行 1 回ごとに 1 つの会話
  - 同じ会話に続ける: オートメーションごとに 1 つの会話に、実行ごとの「指示 → 回答」が古い順に並びます（一度に 20 回分。「さらに前の実行を表示」で遡れます）
- 上限到達・使えないコネクタ（API キーが未登録か、機能が無効）・再ログイン待ちで実行されなかった回も、理由つきで出ます。
- 読み取り専用です。続けて聞くときは「この結果について質問する」を押すと、指示と結果を引用した下書きが入力欄に入るので、質問を書き足して送信します（普通の会話として始まります）。
- 一覧の「×」はチャットの一覧から消すだけで、オートメーション画面の実行履歴は残ります。「同じ会話に続ける」の会話は、次の実行があると過去の実行も含めて一覧に戻ります（Copilot は過去のやり取りを踏まえて答えるため）。
- オートメーション画面の実行詳細の「チャットで見る」から、その実行をチャットで開けます。
- チャットに出るのは、この表示に対応したバージョン以降に記録された実行だけです。それより前の実行はオートメーション画面の実行履歴で確認します。
- 1 回の実行で記録する途中経過（ツールの呼び出しなど）は最新の 200 件までです。省略した場合はその件数を表示します。
- ブラウザのスクリーンショットは 3 日で削除されるため、それより古い実行では画像が表示されません。

## Web の参照とブラウザ

- `web_fetch` とブラウザ（`browser_*` ツール）は、外部の http/https サイトならドメインを問わず参照できます。
- 次の接続は拒否します（`netguard.py`）。
  - 内部宛先: `localhost`、プライベート・ループバック・リンクローカル（`169.254.169.254` のメタデータなど）の IP。名前解決した結果が内部の IP になるホストも含みます。
  - API キーを URL に含めるサービス（`CONNECTOR_HOSTS`）。コネクタのツールだけが使えます。
  - 機微情報（マイナンバー・カード番号・口座番号・パスワード）や秘密情報を含む URL。
- ブラウザはコンテナ内のヘッドレス Chromium（Playwright）です。
  - 通信はすべてアプリ内の中継プロキシを通り、リダイレクト先やページ内の通信も同じ判定をします。接続先は判定済みの IP に固定します。
  - 同時に開けるのは 2 セッションまでで、ページは回答（オートメーションは 1 回の実行）ごとに閉じます。使っていないときは Chromium も終了します。
  - パスワード・カード情報・確認コードの欄、password 欄のあるフォーム（ログイン・会員登録）、機微情報・秘密情報を含む値は入力できません。ダウンロードと動画の読み込みはしません。
  - 本文は 15,000 文字、URL は 2,048 文字、タイトルは 500 文字までです。長すぎるリンクや入力欄のセレクタは省き、結果全体も JSON で 64 KiB 以下に切り詰めます（`result_truncated` で通知）。
  - スクリーンショットは `/data/app/browser-screenshots/` に最大 200 枚保存します。保存・アプリ起動・画像取得時に 3 日を過ぎた画像を削除し、期限切れは配信しません。配信は認証必須・`Cache-Control: no-store` で、モデルには画像を渡しません。
- オートメーションでブラウザを使うときは、コネクタの「ブラウザ（Playwright）」を選びます。
- メモリが足りないなど、ブラウザを止めたいときは環境変数 `LH_BROWSER_ENABLED=false` を設定します。チャットのツールから外れ、ブラウザを選んだオートメーションはエラーになります。

## コネクタ（外部 API）の追加

1. `app/backend/src/life_helper/connectors/` に `Connector` を継承したクラスを作る（接続先ホスト・必要なシークレット名・呼び出し間隔）。
2. `connectors/registry.py` でツールとして登録する（`ToolSpec(..., connector="名前")`）。
3. キーを URL に含める API は、`netguard.py` の `CONNECTOR_HOSTS` に追加して `web_fetch` やブラウザから直接呼べないようにする。
4. `config.py` の `Settings`、`infra/*.bicep` のシークレット、`infra/main.parameters.json`、`scripts/setup-cicd.ps1` のシークレット一覧に追加する。
5. 有料のサービスは、使う前に費用を判断する。

## 投資信託の基準価額（取得元の追加）

基準価額は株価（Yahoo Finance）とは別に取得します（`POST /api/portfolio/refresh-prices` が両方を別々に実行）。主な取得元は
[投資信託協会 投信総合検索ライブラリー](https://toushin-lib.fwg.ne.jp/)で、すべての運用会社のファンドをファンド名で検索でき、ISIN で基準価額の CSV を取得できます。
楽天投信投資顧問・大和アセットマネジメントの公式 CSV は予備として残しています。

| 取得元 | 取得先 | コード | どこで分かるか |
|---|---|---|---|
| 投資信託協会（主） | [投信総合検索ライブラリー](https://toushin-lib.fwg.ne.jp/) | ISIN（`JP` で始まる 12 桁） | 名前が一致すれば自動で紐付く。「取得元を設定」でファンド名から候補を検索できる |
| 楽天投信投資顧問（予備） | [基準価額の CSV](https://www.rakuten-toushin.co.jp/fund/nav/) | チャート CSV の 6 桁番号 | ファンドページの HTML にある CSV のリンク（`chart_100105.csv` なら `100105`） |
| 大和アセットマネジメント（予備） | [基準価額の CSV](https://www.daiwa-am.co.jp/funds/) | 4 桁のファンドコード | ファンドページの URL（`/funds/detail/3242/detail_top.html` なら `3242`） |

三菱UFJアセットマネジメントの投信情報 API は、CloudFront の WAF にすべて拒否される（HTTP 403）ため廃止しました（#22）。
保存済みの `mufg_api` の紐付けは、ISIN があれば投資信託協会の取得元に自動で移り、なければ未設定に戻ります（次の「評価額を計算」で名前から紐付け直します）。
オートメーションの `connectors` に残っている `mufg_api` は `toushin_lib` として扱います。

「評価額を計算」は、取得元が未設定の投資信託を先に紐付けてから基準価額を更新します（`market/funds.py` の `auto_link_funds()`）。

- 証券会社の銘柄名を正規化し（全角・半角、空白、括弧、`・` を無視）、公式名称、または公式名称＋愛称と**完全に一致する公式ファンドが 1 つだけ**のときだけ紐付ける。
  例: SBI の `楽天・シュワブ・高配当株式・米国ファンド(四半期決算型)(楽天・SCHD)` は、公式名称＋愛称（`楽天・ＳＣＨＤ`）と一致する。
- ライブラリーの検索は愛称付きの名前を見つけられないため、末尾の括弧を 1 つずつ外した名前でも検索する（最大 3 通り）。
  すべてのページを読み、100 件を超える場合は一意と判断できないので紐付けない。
- 一致が複数ある、保有中の基準価額と公式の基準価額が 2 倍以上違う（別ファンドや口数単位の違い）、一致がない、のいずれかの場合は紐付けず、画面に理由を表示する。
  検索に失敗した場合は「一致なし」ではなくエラーとして表示する。
- 利用者が「手入力」を選んだファンドは紐付けない。検索中に銘柄が変更された場合も紐付けない。

基準価額の CSV は ISIN と協会コードの組で取得しますが、協会コードが別ファンドのものでも**黙ってそのファンドの CSV を返します**。
そのため協会コードは、検索結果や保存済みの値ではなく、必ずその ISIN のファンドページ（`FDST030000?isinCd=...`）から読み、
ページに ISIN が含まれ、協会コードが 1 つだけのときだけ使います（確認済みの組はプロセス内でキャッシュ）。

証券会社 CSV の基準価額には、中の基準日ではなく取り込んだ日が付きます（画面では「CSV 取込日」と表示）。そのため、公式の基準価額は、
取り込んだ日から 10 日以内の基準日であれば、証券会社 CSV の値より古い日付でも置き換えます（`Holding.apply_price()`）。

取得元を追加する手順:

1. `connectors/fund_nav.py` に `FundNavConnector`（API）または `FundCsvConnector`（公式 CSV）を継承したクラスを作り、
   `provider`・`manager`・`price_unit`・接続先ホストを定義する。
   `fund_nav()` は `fund_code` / `name` / `nav` / `price_unit` / `date` / `source` / `source_url` を返し、
   `search_funds(name, exhaustive=...)` は `exact`（名前が完全に一致するか）付きの候補を返す（名前で検索できなければ `[]`）。
   `FundCsvConnector` は `code_shape`（ファンドコードの形式）と `csv_url()` を定義すれば、基準日・基準価額の列を名前で探して最新行を使う。
2. 取得先は公式に案内されている URL 形式だけにする（画面内部の非公開エンドポイントや利用者が入力した URL は取得しない）。
   受け取った基準価額・基準日・ファンドコードは `nav_amount()` / `nav_date()` などで必ず検証する。
3. `market/portfolio.py` の `FundProvider`・`PriceSource`・`OFFICIAL_NAV_SOURCES` に提供元名を追加し、`connectors/registry.py` に登録する。
4. `app/frontend/src/pages/Portfolio.tsx` の `SOURCE_LABELS`（と `CODE_HINTS`）に表示名を追加する。

自動で紐付けられなかったファンドは「取得元を設定」で候補から選ぶか、コードを指定するか、「手入力」を選んで公式サイトの基準価額を入力します。
取得に失敗したファンドは直前の基準価額を残し、ほかのファンドの更新は続行します。
